# Небольшой план улучшений

После объединения проектов я бы ограничился тремя следующими шагами:

1. **Команда `gearflow doctor`.** Проверять доступность команд, настройку SSH,
   подпись Git и окружение hasher до начала обновления. Это даст понятную
   диагностику вместо остановки посреди процесса.
2. **Предварительный план обновления.** Показывать выбранный upstream-тег,
   будущие Version/Release, изменения rules и адрес push до merge. Отдельный
   режим `--plan` стоит делать без изменения рабочего дерева и Git config;
   нынешний `--dry-run` относится только к сканированию задачи.
3. **Расширить существующий конфиг.** В конфиг проверок
   `~/.config/gearflow/config.json` добавить настройки SSH-хостов, ветки и
   параметров пересборки. Переменные окружения оставить приоритетнее файла.

По мере появления реальных проблем полезно дополнять тестовые примеры вывода
Girar и `.gear/rules`. Полную перепись рабочего процесса на Python имеет смысл
делать постепенно, если Bash начнёт мешать сопровождению.

Это предложения для следующих изменений; перечисленные команды и настройки
пока не реализованы.
